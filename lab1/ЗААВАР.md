## 3. Онол — товч

**Виртуалчлал** (Lec1): нэг физик компьютер дээр хэд хэдэн үйлдлийн системийг зэрэг ажиллуулах технологи. *Hypervisor* (VMM) нь техник хангамжийг хийсвэрлэж, guest OS бүрт "өөрийн компьютер" мэт харагдуулна.

| Хэрэгсэл | Төрөл | Онцлог |
|---|---|---|
| **Hyper-V** | Type-1 (техник хангамж дээр шууд) | Windows Pro/Enterprise-д л байдаг |
| **VirtualBox** | Type-2 (host OS дээр ажилладаг программ) | Бүрэн GUI-тэй VM, илүү RAM/диск иддэг |
| **WSL2** | Хөнгөн Hyper-V VM дотор жинхэнэ Linux кернел | Windows Home-д ч ажиллана, хурдан асна, Windows-той файл солилцоход амар |

**Яагаад WSL2 сонгосон бэ:** Windows 11 *Home* дээр Hyper-V байхгүй; WSL2 нь Microsoft-ын дэмжлэгтэй, нөөц бага хэрэглэдэг (RAM-ыг динамикаар авна), жинхэнэ Linux кернел (системийн дуудалт, `fork`, `strace` бүгд ажиллана), Windows-ийн диск `/mnt/c` дор шууд харагдана. **Ubuntu 22.04 LTS** — урт хугацааны дэмжлэгтэй (2027 он хүртэл), хамгийн өргөн хэрэглэгддэг, баримт бичиг ихтэй.

**SSH (Secure Shell):** клиент–сервер протокол (port 22). Холболтыг шифрлэдэг. Нэвтрэх хоёр арга: нууц үг эсвэл **түлхүүр хос** (public/private key). Энд **ed25519 түлхүүр** ашигласан: *public key* нь VM-ийн `~/.ssh/authorized_keys`-д, *private key* нь Windows-д байна — сервер клиентээс private key-ээр гарын үсэг зурахыг шаардаж шалгадаг тул нууц үг сүлжээгээр дамжихгүй.

**Хөрвүүлэлт:** C код `gcc`-ээр тухайн OS/CPU-ийн **машины код** болно (Windows-д `.exe` PE формат, Linux-д ELF) — тиймээс OS бүр дээр тусад нь хөрвүүлнэ. Java код `javac`-аар **bytecode** (`.class`) болж **JVM** дээр ажилладаг тул нэг `.class` хоёр OS дээр адилхан ажиллана ("write once, run anywhere").

## 4. Алхам алхмаар

### Алхам 1 — Виртуал систем (WSL2 Ubuntu)

Суулгасан арга (аль хэдийн хийгдсэн, бичлэгт тайлбарлахад):
```powershell
# PowerShell (админ) — WSL болон Virtual Machine Platform-ийг асааж Ubuntu суулгана
wsl --install -d Ubuntu-22.04
```
(Эсвэл *Turn Windows features on or off* → ✅ *Windows Subsystem for Linux*, ✅ *Virtual Machine Platform* → дахин ачаалах.)

Шалгах (PowerShell):
```powershell
wsl -l -v                 # Ubuntu-22.04  Running  2   ← VERSION 2 = WSL2
wsl -d Ubuntu-22.04       # Ubuntu руу орох
```
Ubuntu дотор:
```bash
cat /etc/os-release | head -2    # Ubuntu 22.04.5 LTS
uname -a                         # Linux ... microsoft-standard-WSL2 x86_64
nproc; free -h; df -h /          # CPU, RAM, дискний нөөц
```

### Алхам 1d — Сүлжээ ба файл хуулах

**Сүлжээ.** WSL2 нь **NAT** горимтой: Windows дээр `vEthernet (WSL)` гэсэн виртуал адаптер (172.24.0.1) үүсч, VM нь 172.24.x.x хаяг авна.
```bash
ip addr show eth0 | grep inet    # inet 172.24.6.185/20   ← VM-ийн IP
ip route | head -1               # default via 172.24.0.1  ← Windows (gateway)
ping -c 2 172.24.0.1             # VM → Windows
ping -c 2 8.8.8.8                # VM → интернэт
```
Windows талаас: `ipconfig` → *vEthernet (WSL)* = 172.24.0.1, `ping 172.24.6.185`.

> IP хаяг WSL дахин асах бүрт солигдож болно — бичлэгийн өмнө `ip addr show eth0`-оор шалга. `localhost` гэж хандвал Windows автоматаар VM руу дамжуулдаг (localhost forwarding).

**Файл хуулах — 3 арга:**
```bash
# 1) Windows-ийн диск /mnt/c дор холбогдсон байдаг
cp "/mnt/c/lesson 2026/F.CSA302/lab1/test.txt" ~/
cat ~/test.txt                   # Hello from Windows
```
2) **File Explorer** хаягийн мөрөнд `\\wsl$\Ubuntu-22.04\root` гэж бичээд файлаа чирж оруулна.
3) **SSH-ээр** (Алхам 2-ын дараа) — PowerShell:
```powershell
pscp -i $HOME\.ssh\wsl_lab1.ppk test.txt root@localhost:/root/
```

### Алхам 2 — SSH (OpenSSH server + PuTTY)

VM дээр хийгдсэн тохиргоо:
```bash
apt install openssh-server          # SSH сервер (суусан)
systemctl enable --now ssh          # асаах + ачаалах бүрт автоматаар асах
systemctl status ssh                # active (running)
ss -tlnp | grep :22                 # 0.0.0.0:22 дээр сонсож байна
cat ~/.ssh/authorized_keys          # ssh-ed25519 AAAA... lab1-wsl  ← public key
```
Windows дээрх түлхүүрүүд (`C:\Users\Dell\.ssh\`):

| Файл | Юу вэ |
|---|---|
| `wsl_lab1` | Private key (OpenSSH формат) — хэнд ч бүү өг |
| `wsl_lab1.pub` | Public key — VM-ийн `authorized_keys`-д хуулсан |
| `wsl_lab1.ppk` | Private key-ийн PuTTY формат (`puttygen`-ээр хөрвүүлсэн) |

Түлхүүр хэрхэн үүсгэсэн (тайлбарлахад):
```bash
ssh-keygen -t ed25519 -f ~/.ssh/wsl_lab1             # Windows дээр түлхүүр хос үүсгэх
cat wsl_lab1.pub >> /root/.ssh/authorized_keys       # VM дээр public key-г зөвшөөрөх
puttygen wsl_lab1 -O private -o wsl_lab1.ppk         # PuTTY формат руу хөрвүүлэх
```

**PuTTY-ээр нэвтрэх:**
1. PuTTY нээ → *Session*: Host Name = `localhost` (эсвэл `172.24.6.185`), Port = `22`, Connection type = **SSH**.
2. *Connection → Data*: Auto-login username = `root`.
3. *Connection → SSH → Auth → Credentials*: Private key file = `C:\Users\Dell\.ssh\wsl_lab1.ppk`.
4. *Session* руу буцаж Saved Sessions = `WSL Lab1` → **Save** → **Open**.
5. Анх холбогдоход *host key* асууна → **Accept** (сервер мөн гэдгийг баталгаажуулж байна).

Нэвтэрсний дараа хавтас, файлд хандах:
```bash
whoami; hostname                                  # root, DESKTOP-RA4LUQ2
ls "/mnt/c/lesson 2026/F.CSA302"                  # Windows-ийн файлууд
cd "/mnt/c/lesson 2026/F.CSA302/lab1" && ls
```
PowerShell-ийн OpenSSH клиентээр ч болно: `ssh -i $HOME\.ssh\wsl_lab1 root@localhost`

### Алхам 3 — VS Code

Суусан. lab1 хавтсыг нээ: *File → Open Folder* эсвэл PowerShell-д `code .`
Санал болгох өргөтгөл: **C/C++** (Microsoft), **Extension Pack for Java**, **WSL** (VS Code-оор VM доторх файлыг шууд засах — Ubuntu дотроос `code .`).

### Алхам 4 — Hello world (C, Java) хоёр систем дээр

**Үндсэн систем — Windows PowerShell** (`lab1` хавтсанд):
```powershell
gcc hello.c -o hello.exe
.\hello.exe                     # Hello world
java HelloWorld.java            # Hello world   (source-launcher: шууд ажиллуулна)
# эсвэл хоёр алхмаар:
javac HelloWorld.java; java HelloWorld
```
**Виртуал систем — PuTTY/Ubuntu**:
```bash
cd "/mnt/c/lesson 2026/F.CSA302/lab1"
gcc hello.c -o /tmp/hello && /tmp/hello        # Hello world
java HelloWorld.java                           # Hello world
file /tmp/hello                                # ELF 64-bit ... (Linux-ийн формат)
```
> `.exe`-г Linux дээр, ELF-ийг Windows дээр ажиллуулж болохгүй — машины код OS-оос хамаардаг (Lec2: *Программ яагаад OS хамааралтай вэ*).

## 6. Багш асууж магадгүй асуултууд

| Асуулт | Товч хариулт |
|---|---|
| WSL1 ба WSL2-ийн ялгаа? | WSL1 Linux-ийн систем дуудалтыг Windows кернелд *хөрвүүлдэг*; WSL2 жинхэнэ Linux кернелийг хөнгөн VM-д ажиллуулдаг → бүрэн нийцтэй, файлын систем хурдан. |
| Type-1 ба Type-2 hypervisor? | Type-1 техник хангамж дээр шууд (Hyper-V, VMware ESXi); Type-2 host OS дээр программ шиг (VirtualBox, VMware Workstation). |
| NAT гэж юу вэ? | VM дотоод хаягтай (172.24.x.x), гадагш гарахдаа host-ийн хаягаар "нэрээ сольж" гардаг. Гаднаас VM рүү шууд хандахгүй. |
| SSH яагаад аюулгүй вэ? | Бүх траффик шифрлэгдэнэ; түлхүүрээр нэвтрэхэд нууц үг дамжихгүй; host key-ээр серверийг баталгаажуулна (MITM-ээс хамгаална). |
| Public, private key-ийн үүрэг? | Public key — серверт өгнө (цоож), private key — зөвхөн өөрт (түлхүүр). Сервер санамсаргүй өгөгдөл илгээж, клиент private key-ээр гарын үсэг зурж баталдаг. |
| C болон Java хөрвүүлэлтийн ялгаа? | C → тухайн OS/CPU-ийн машины код (ELF/PE). Java → bytecode → JVM тайлбарлаж/JIT-ээр ажиллуулна. |
| `printf` нь ямар систем дуудалт хийдэг вэ? | Linux дээр `write(1, ...)` (Lec2: стандарт C сан → систем дуудалт). `strace ./hello` гэж шалгаж болно. |
