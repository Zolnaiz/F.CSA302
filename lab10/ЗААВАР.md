## 1. Онол — товч

- **HDD-ийн хандалт** = хайлт (seek, толгойг цилиндр рүү зөөх) + эргэлтийн хүлээлт + дамжуулалт. Хайлт хамгийн үнэтэй → дискний хуваарилалт толгойн шилжилтийг багасгана.
- **FCFS** — ирсэн дарааллаар. Шударга, гэхдээ толгой нааш цааш их гүйнэ.
- **SSTF** — хамгийн ойрыг. Голын цилиндрийг илүүд үзэж, захынх хомсдолд орж болно (11.2).
- **SCAN** (цахилгаан шат) — нэг зах хүртэл явж замдаа үйлчилнэ, эргээд буцна.
- **C-SCAN** — зөвхөн нэг чиглэлд үйлчилнэ, зах хүрээд эхэнд нь шууд буцна → хүлээлтийн хугацаа жигд.
- **Үр ашигтай хурд** = x / (L + x/R); **ашиглалт** = x / (L·R + x). 25%-д хүрэх хамгийн бага хэмжээ x = L·R/3 (11.7).
- **RAID 1** — толин хуулбар, уншилтыг аль ч дискээс (11.8). **NVM** — хөдөлгөөнт хэсэггүй, хурдан (11.10).

## 2. Программ — `disk_sched.c` (11.27)

- 0–4999 цилиндр, `rand() % 5000`-аар 1000 хүсэлт. Толгойн эхний байрлал — командын мөрийн аргумент.
- `fcfs()` — хүсэлт хоорондын зайн нийлбэр.
- `scan()` — эхлээд **0 руу** (номын Fig. 11.7 шиг), эргээд хамгийн том хүсэлт хүртэл: `head + max`.
- `cscan()` — дээш **4999** хүртэл, 0 руу буцаад (буцах шилжилтийг **тооцсон**), толгойноос доорх хамгийн том хүсэлт хүртэл.
- Сонголт: `-s seed` (давтагдах), `-n` хүсэлтийн тоо, `-c` цилиндрийн тоо, `-r "…"` тодорхой хүсэлтүүд.

## 5. Багш асууж магадгүй

| Асуулт | Хариулт |
|---|---|
| SCAN яагаад эхлээд 0 руу явдаг вэ? | Ном (Fig. 11.7)-д толгой 0 руу хөдөлж байгаа гэж үздэг. Чиглэл нь параметр — нөгөө чиглэлээр явбал дүн өөр. |
| C-SCAN-д буцах замыг яагаад тоолсон бэ? | Толгой физикээр 4999-өөс 0 руу зөөгддөг тул шилжилт мөн. Зарим ном үүнийг тоолдоггүй — тайланд тэмдэглэсэн. |
| C-SCAN-ийн давуу тал? | Бүх цилиндрийн хүлээлтийн хугацаа жигд; SCAN-д захын цилиндрүүд хоёр гаталтын хооронд удаан хүлээдэг. |
| SSD-д дискний хуваарилалт хэрэгтэй юу? | Бараг үгүй — хайлт байхгүй тул Linux NVM-д `none`/`mq-deadline` хэрэглэдэг. |
| 11.7c-ийн 25 KB хаанаас? | x/(L·R + x) = 0.25 → x = L·R/3 = 0.015 × 5·10⁶ / 3 = 25 000 байт. |
