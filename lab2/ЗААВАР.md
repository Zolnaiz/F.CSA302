## 3. Онол

**Систем дуудалт (system call)** — OS-ийн сервист хандах программчлагдах интерфейс (Lec2 слайд 12). Программ ихэвчлэн шууд биш, **API**-гаар дамжуулан дууддаг:

| API | Хэрэглэгддэг OS |
|---|---|
| **POSIX API** | UNIX, Linux, macOS |
| **Win32 API** | Windows |
| **Java API** | JVM |

Систем дуудалт бүр **дугаартай**; *system-call interface* нь тэр дугаараар индексжүүлсэн хүснэгтээс кернелийн функцийг олж дуудна, хэрэглэгчийн горимоос **кернелийн горимд** шилжинэ (Lec2 слайд 15).

**§2.3 / Lec2 слайд 13 — файл хуулах дуудалтын дараалал:**
```
Оролтын файлын нэрийг авах      → дэлгэцэнд prompt бичих (write), гарнаас унших (read)
Гаралтын файлын нэрийг авах     → write, read
Оролтын файлыг нээх             → файл байхгүй бол → алдаа, зогсоох
Гаралтын файлыг үүсгэх          → файл байвал → алдаа/асуух
Давталт: оролтоос унших → гаралт руу бичих   (EOF эсвэл алдаа гартал)
Гаралтын файлыг хаах
Дэлгэцэнд дууссан мессеж бичих
Хэвийн дуусах (exit)
```

**POSIX ↔ Windows харгалзаа** (Lec2 *Windows, Unix жишээ* хүснэгт):

| Үйлдэл | POSIX | Windows API |
|---|---|---|
| Файлын мэдээлэл | `stat()` | `GetFileAttributesA()`, `GetFileInformationByHandle()` |
| Нээх | `open(O_RDONLY)` | `CreateFileA(GENERIC_READ, OPEN_EXISTING)` |
| Үүсгэх | `open(O_WRONLY \| O_CREAT \| O_TRUNC)` | `CreateFileA(GENERIC_WRITE, CREATE_ALWAYS)` |
| Унших | `read()` | `ReadFile()` |
| Бичих | `write()` | `WriteFile()` |
| Хаах | `close()` | `CloseHandle()` |
| Алдааны код | `errno` + `strerror()` | `GetLastError()` + `FormatMessageA()` |
| Файлын тодорхойлогч | `int` file descriptor (0,1,2,3…) | `HANDLE` |
| Дуусах | `exit()` | `ExitProcess()` (C-д `return`) |

## 4. Код хэрхэн ажилладаг вэ

Хоёр файл хоёулаа кодон дээрх **1–7** гэсэн тайлбартай алхмуудтай:

| Алхам | `FileCopy.c` (POSIX) | `FileCopy_win.c` (Windows) |
|---|---|---|
| **1. Нэр асуух** | `read_line()`: `printf` + `fgets`, `'\n'`-г арилгана, хоосон/хэт урт нэрийг шалгана | ижил |
| **2. Эх файл шалгах** | `stat(src)` → байхгүй бол `ENOENT`; `S_ISREG` — энгийн файл мөн эсэх (хавтас бол алдаа) | `GetFileAttributesA` → `INVALID_FILE_ATTRIBUTES`; `FILE_ATTRIBUTE_DIRECTORY` |
| **3. Хүлээн авах файл байгаа бол** | `stat(dst)` → **ижил файл** эсэх (`st_dev` + `st_ino` тэнцүү бол алдаа), хавтас эсэх, **дарж бичих эсэхийг асууна** (y/n) | `GetFileInformationByHandle` → volume serial + file index-ээр ижил файл эсэх; асууна |
| **4. Эх файл нээх** | `open(src, O_RDONLY)` | `CreateFileA(..., GENERIC_READ, ..., OPEN_EXISTING, ...)` |
| **5. Хүлээн авах файл үүсгэх** | `open(dst, O_WRONLY\|O_CREAT\|O_TRUNC, эх файлын эрх)` | `CreateFileA(..., GENERIC_WRITE, ..., CREATE_ALWAYS, ...)` |
| **6. Хуулах давталт** | `read(in, buf, 4096)` → `0` бол EOF; `write_all()` — `write()` бүх байтыг нэг дор бичихгүй байж болох тул давтана; `EINTR` (сигналаар тасарсан) бол дахин оролдоно | `ReadFile` → `nread == 0` бол EOF; `WriteFile` → `nwritten != nread` бол алдаа |
| **7. Хаах** | `close()`-ийн буцаах утгыг ч шалгана (дискэнд бичих алдаа энд гарч болно) | `CloseHandle()` |

**Яагаад "ижил файл" шалгалт хэрэгтэй вэ?** `./FileCopy` → `a.txt` → `a.txt` гэвэл `O_TRUNC` эх файлыг 0 байт болгож **өгөгдөл устна**. Нэр өөр ч (`a.txt` ба `./a.txt`) ижил файл байж болох тул нэрээр биш **inode**-оор харьцуулна.

**Яагаад 4096 байтын буфер?** Санах ойн нэг хуудас (page) 4 KB; цөөн систем дуудалтаар их өгөгдөл хуулна. 5 MB файл = 5 000 000 / 4096 ≈ 1221 удаа уншиж-бичнэ. Хэмжсэн нь: `strace -c -e trace=read,write ./FileCopy` → **1224 read, 1224 write** (1221 өгөгдөл + EOF + stdin/stdout-ийн prompt).

## 8. strace — Linux дээр систем дуудалт хянах

```bash
strace ./FileCopy                          # бүх дуудалт (stderr руу)
strace -o trace.txt ./FileCopy             # файл руу
strace -e trace=openat,read,write,close ./FileCopy   # зөвхөн файлын дуудалтууд
strace -c ./FileCopy                       # дуудалт бүрийн тоо, хугацааны статистик
```
**Гол мөрүүд** (`strace_output.txt`, 38–52-р мөр):
```
write(1, "Enter source file name: ", 24) = 24          ← printf → write(stdout)
read(0, "input.txt\noutput.txt\n", 4096) = 21          ← fgets → read(stdin)
write(1, "Enter destination file name: ", 29) = 29
newfstatat(AT_FDCWD, "input.txt", {...S_IFREG...}) = 0 ← stat: эх файл байна
newfstatat(AT_FDCWD, "output.txt", ...) = -1 ENOENT   ← хүлээн авах файл байхгүй
openat(AT_FDCWD, "input.txt", O_RDONLY) = 3            ← fd 3
openat(AT_FDCWD, "output.txt", O_WRONLY|O_CREAT|O_TRUNC, 0777) = 4   ← fd 4
read(3, "Hello from Lab 2 - ..."..., 4096) = 49
write(4, "Hello from Lab 2 - ..."..., 49) = 49
read(3, "", 4096) = 0                                  ← EOF
close(3) = 0
close(4) = 0
write(1, "Copied 49 bytes ...", 50) = 50
exit_group(0) = ?
```
**Эхний ~35 мөр** нь программ ачаалагдах үеийнх: `execve` (программыг санах ойд ачаалах), `mmap`/`mprotect` (libc сан холбох), `brk` (heap). Сурах бичигт хэлсэнчлэн: *энгийн программ ч олон систем дуудалт хийдэг*. Мөн `printf`/`fgets` нь C сангийн функц бөгөөд дотроо `write`/`read` систем дуудалт хийдэг (Lec2: *Стандарт C сангийн жишээ*).

> `0777` эрх гарч байгаа нь `/mnt/c` (Windows диск) Linux-ийн эрхийг хадгалдаггүйтэй холбоотой. Linux диск дээр (`~/`) ажиллуулбал `0644` гарна.

## 9. Windows — дибаггер (gdb)-ээр хянах

Windows-д strace байхгүй. Lec2 слайд 47-д заасан **gdb**-ээр Win32 API дуудалт бүрийн өмнө/дараа зогсоож утгыг харна.

**Автомат мөрдөлт (strace-тэй төстэй гаралт):**
```powershell
gdb -q -batch -x trace_win.gdb FileCopy.exe
```
```
GetFileAttributesA("input.txt")                          = 0x20      ← FILE_ATTRIBUTE_ARCHIVE (энгийн файл)
CreateFileA("input.txt", GENERIC_READ, OPEN_EXISTING)  = handle 0xa8
CreateFileA("win_out.txt", GENERIC_WRITE, CREATE_ALWAYS) = handle 0xac
ReadFile(0xa8, buf, 4096)                            = 49 bytes
WriteFile(0xac, buf, 49)                             = 49 bytes
ReadFile(0xa8, buf, 4096)                            = 0 bytes   ← EOF
CloseHandle(0xa8)
CloseHandle(0xac)
Copied 49 bytes from 'input.txt' to 'win_out.txt'.
```
**Гараар (интерактив):**
```
gdb -q FileCopy.exe
(gdb) break 85          # CreateFileA(src) мөр
(gdb) break 136         # ReadFile мөр
(gdb) run               # нэрсээ гараар оруулна
(gdb) print src         # $1 = "input.txt"
(gdb) next              # CreateFileA-г гүйцэтгэх
(gdb) print in          # $2 = (HANDLE) 0xa8   ← POSIX-ийн fd 3-тай адил
(gdb) continue
(gdb) next
(gdb) print nread       # $3 = 49
(gdb) continue
(gdb) quit
```
Нэмэлт: **Process Monitor** (Sysinternals) нь Windows-ийн файлын үйлдлүүдийг GUI-ээр харуулдаг хэрэгсэл.

## 11. Багш асууж магадгүй асуултууд

| Асуулт | Товч хариулт |
|---|---|
| Систем дуудалт ба API-ийн ялгаа? | API (жнь `fopen`, `printf`) нь сангийн функц; дотроо систем дуудалт (`open`, `write`) хийж кернел рүү шилждэг. API нь зөөвөрлөх чадвартай, систем дуудалт OS бүрт өөр. |
| Хэрэглэгчийн ба кернелийн горим? | Систем дуудалт хийхэд CPU mode bit-ийг сольж кернелийн горимд шилжинэ (trap), дуусахад буцна (Lec1 *Dual-mode*). |
| Файл тодорхойлогч 0, 1, 2 юу вэ? | stdin, stdout, stderr. Тиймээс шинээр нээсэн файл 3, 4 дугаар авсан. |
| `O_TRUNC` юу хийдэг? | Файл байвал түүнийг 0 урттай болгоно (хуучин агуулгыг устгана). |
| `read` 0 буцаавал? | Файлын төгсгөл (EOF). -1 бол алдаа (`errno`). |
| Яагаад `write`-ийг давталтаар бичсэн бэ? | `write` хүссэнээсээ цөөн байт бичиж болно (partial write) — бүгдийг бичтэл давтана. |
| Параметрийг кернелд яаж дамжуулдаг вэ? | Регистрээр, эсвэл санах ой дахь блок/хүснэгтийн хаягаар, эсвэл стекээр (Lec2 *Параметр дамжуулах*). |
| strace хэрхэн ажилладаг вэ? | `ptrace()` систем дуудалтаар хүү процессыг хянаж, систем дуудалт бүрийн орох/гарах үед зогсоож мэдээллийг хэвлэнэ. |
