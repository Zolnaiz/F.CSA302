## 2. Онол (Lec3)

**Процесс** — биелж буй программ (актив), **программ** — диск дээрх executable файл (пассив). Процессын бүтэц: *text* (код), *data* (глобал хувьсагч), *heap* (динамик с/о), *stack* (локал хувьсагч, буцах хаяг).

**ПУБ (PCB, процесс удирдлагын блок)** — процессын төлөв, программын тоолуур, CPU регистрүүд, хуваарилалтын мэдээлэл, с/о-н мэдээлэл, нээсэн файлууд. Linux-д `task_struct`.

**Процесс дээрх үйлдлүүд (UNIX):**

| Дуудалт | Юу хийдэг |
|---|---|
| `fork()` | Эцэг процессын **хуулбар** болох хүү процесс үүсгэнэ. Эцэгт хүүгийн PID, хүүд **0** буцаана, алдаа бол -1. |
| `exec()` (`execvp`) | Процессын с/о-г **шинэ программаар солино** (PID хэвээр). Амжилттай бол буцахгүй. |
| `wait()` / `waitpid()` | Эцэг хүүгээ дуусахыг хүлээж, төлөвийн өгөгдлийг авна → OS хүүгийн нөөцийг чөлөөлнө. |
| `exit()` | Процесс өөрийгөө дуусгана. |

**Zombie** — дууссан боловч эцэг нь `wait()` дуудаагүй тул ПУБ нь процессын хүснэгтэд үлдсэн хүү процесс (`ps`-д `Z`, `<defunct>`). **Orphan** — эцэг нь түрүүлж дууссан хүү; Linux-д `init`/`systemd` (PID 1) үрчилж аваад `wait()` хийдэг.

**IPC (процесс хоорондын харилцаа)** — хоёр загвар:

| | Дундын санах ой (shared memory) | Мессеж дамжуулалт (message passing) |
|---|---|---|
| Санаа | Хоёр процесс нэг с/о-н хэсгийг хуваалцана | `send()`/`receive()` |
| Хурд | Хурдан (кернел зөвхөн үүсгэхэд оролцоно) | Удаан (мессеж бүр систем дуудалт) |
| Синхрончлол | Программист өөрөө хариуцна | Кернел хариуцна |
| POSIX | `shm_open` → `ftruncate` → `mmap` → ... → `shm_unlink` | `pipe()`, сокет, message queue |

**Ordinary pipe** — нэг чиглэлтэй (`fd[1]`-д бичиж, `fd[0]`-оос уншина), зөвхөн эцэг–хүү процесс хооронд (Windows-д *anonymous pipe*). **Named pipe** (FIFO) — хоёр чиглэлтэй, эцэг–хүү хамааралгүй.

### 3.18 — Zombie процесс (`zombie.c`)

**Санаа:** хүү процесс шууд `exit(0)`; эцэг нь `wait()` **дуудахгүй** 20 сек унтана → хүү zombie болно.
```c
pid_t pid = fork();
if (pid == 0) { exit(0); }          // хүү: шууд дуусна
sleep(2); system("ps -l");          // эцэг: wait() дуудахгүй, zombie-г харуулна
sleep(18);
```
**Ажиллуулах:**
```bash
./zombie                 # эсвэл номын дагуу: ./zombie &   дараа нь   ps -l
```
**Хүлээгдэх:**
```
Parent PID=431, child PID=432. Sleeping 20 s (no wait)...
F S   UID     PID    PPID  C PRI  NI ADDR SZ WCHAN  TTY          TIME CMD
1 Z     0     432     431  0  80   0 -     0 -      pts/0    00:00:00 zombie <defunct>
```
`S` багана = **Z**, PPID = эцгийн PID. **Zombie-г арилгах:** `kill -9 <эцгийн PID>` → хүү orphan болж `init` үрчлээд `wait()` хийнэ.

### 3.19 — Командын хугацаа хэмжих (`time_shm.c`, `time_pipe.c`)

**Санаа:** `fork()` → хүү **exec-ээс өмнө** `gettimeofday()`-ээр эхлэх хугацааг IPC-ээр эцэгт дамжуулна → `execvp(argv[1], &argv[1])` → эцэг `waitpid()` → төгсгөлийн хугацаа → зөрүү.

| | `time_shm.c` | `time_pipe.c` |
|---|---|---|
| IPC | POSIX дундын санах ой | Ordinary pipe |
| Үүсгэх | `fork()`-оос **өмнө** `shm_open` + `ftruncate` + `mmap(MAP_SHARED)` → хоёулаа хандана | `fork()`-оос өмнө `pipe(fd)` |
| Хүү | `gettimeofday(start, NULL)` — шууд дундын с/о руу бичнэ | `write(fd[1], &start, sizeof start)` |
| Эцэг | хүү дууссаны дараа `start->tv_sec` уншина, `shm_unlink` | `read(fd[0], &start, ...)` |

**Ажиллуулах:**
```bash
./time_shm ls            # ...файлын жагсаалт...  Elapsed time: 0.00661
./time_pipe sleep 1      # Elapsed time: 1.00351
./time_shm nosuchcmd     # execvp: No such file or directory  (exit 127)
```
Хугацаа = `(end.tv_sec - start.tv_sec) + (end.tv_usec - start.tv_usec) / 1e6`.

### 3.20 — PID manager (`pid_manager.c`)

**Санаа:** 300–5000 хүртэлх **4701** PID-ийг **bitmap**-аар удирдана (Linux-ийн арга): бит `i` = 0 бол `MIN_PID + i` чөлөөтэй, 1 бол ашиглагдаж байна. 4701 бит ≈ 147 `unsigned int` ≈ 588 байт.

| API | Хэрэгжүүлэлт |
|---|---|
| `int allocate_map(void)` | `calloc` — бүх битийг 0; амжилттай бол 1, үгүй бол -1 |
| `int allocate_pid(void)` | сүүлд олгосон PID-ээс хойш тойрч хайж 0 бит олоод 1 болгоно; бүгд ашиглагдаж байвал -1 |
| `void release_pid(int pid)` | тухайн битийг 0 болгоно (хүрээнээс гадуурх утгыг үл тооно) |

Битийн үйлдэл: `map[i/32] |= 1u << (i%32)` (тавих), `&= ~(...)` (арилгах), `>> (i%32) & 1` (шалгах).
```bash
./pid_manager
Allocated: 300 301 302
Released 301, next allocation: 303          ← шууд дахин ашиглахгүй (Linux ч мөн адил)
Allocated all 4701 pids (range 300-5000). Next: -1 (expected -1)
Released 4000, next allocation: 4000
```

### 3.21 — Collatz, `fork()` (`collatz.c`)

**Санаа:** n тэгш бол n/2, сондгой бол 3n+1 → 1 хүртэл. **Хүү процесс** дарааллыг хэвлэнэ (эцэг–хүү тусдаа с/о-той тул эцэг хүүгийн тооцоог харахгүй), эцэг `wait()`. Оролтыг `strtol`-оор шалгана (эерэг бүхэл тоо).
```bash
./collatz 35     # 35, 106, 53, 160, 80, 40, 20, 10, 5, 16, 8, 4, 2, 1
./collatz 8      # 8, 4, 2, 1
./collatz -3     # Error: '-3' is not a positive integer
./collatz abc    # Error: 'abc' is not a positive integer
```

### 3.22 — Collatz, дундын санах ой (`collatz_shm.c`)

**Санаа:** номын a–d алхам яг дагасан:
- **a.** эцэг `shm_open` → `ftruncate` → `mmap` (бүтэц: `int count; long terms[4096]`)
- **b.** `fork()`; хүү дарааллыг **дундын с/о-д бичнэ**; эцэг `wait()` — синхрончлол (хүү дуусахаас өмнө эцэг уншихгүй)
- **c.** эцэг дундын с/о-оос хэвлэнэ
- **d.** `munmap` + `shm_unlink` — объектыг устгана
```bash
./collatz_shm 35
35, 106, 53, 160, 80, 40, 20, 10, 5, 16, 8, 4, 2, 1
(printed by parent from shared memory, 14 terms)
```
> 3.21-тэй харьцуулбал: энд **эцэг** хэвлэж байна — учир нь `MAP_SHARED` с/о хоёр процесст ижил физик хуудас руу заадаг.

## 6. Багш асууж магадгүй асуултууд

| Асуулт | Товч хариулт |
|---|---|
| `fork()` юу буцаадаг вэ? | Эцэгт хүүгийн PID (>0), хүүд 0, алдаа бол -1. Нэг дуудалт — хоёр буцалт. |
| `fork()` ба `exec()` ялгаа? | `fork` — шинэ процесс (хуулбар); `exec` — шинэ процесс үүсгэхгүй, одоогийнхын программыг солино. |
| Zombie яагаад үүсдэг вэ, хортой юу? | Эцэг `wait()` хийхгүй бол хүүгийн ПУБ (PID, exit status) үлдэнэ. Олон болвол PID-ийн хүснэгт дүүрнэ. |
| Orphan гэж юу вэ? | Эцэг нь түрүүлж дууссан хүү — `init` (PID 1) үрчилнэ. |
| Copy-on-write гэж юу вэ? | `fork()` хуудсуудыг шууд хуулахгүй, хуваалцаж байгаад аль нэг нь бичих үед л хуулна → хурдан. |
| Дундын с/о-д синхрончлол яагаад хэрэгтэй вэ? | Хоёр процесс зэрэг бичиж/уншвал race condition. Энд `wait()`-ээр синхрончилсон (Lec3: 6, 7-р бүлэгт дэлгэрэнгүй). |
| `shm_unlink` хийхгүй бол? | Объект `/dev/shm/`-д программ дууссан ч үлдэнэ (санах ой эзэлнэ). |
| Pipe-ийн аль төгсгөлийг хаах ёстой вэ? | Хүү зөвхөн бичдэг бол `fd[0]`-г, эцэг зөвхөн уншдаг бол `fd[1]`-г хаана — эс бөгөөс `read` EOF хэзээ ч авахгүй. |
| Ordinary ба named pipe? | Ordinary — нэг чиглэл, эцэг–хүү; named — хоёр чиглэл, хамааралгүй процессууд, файлын системд нэртэй. |
| RPC "exactly once" vs "at most once"? | At most once — timestamp-ээр давхардлыг үл тооно (0 эсвэл 1 удаа). Exactly once — дээр нь ACK + дахин илгээлт → яг 1 удаа. |
