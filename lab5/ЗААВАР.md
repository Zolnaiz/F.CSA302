## 2. Онол (Lec5)

**CPU хуваарилагч** — бэлэн дараалал (ready queue)-аас процесс сонгож CPU цөм оноодог. **Диспетчер** — контекст солих, хэрэглэгчийн горимд шилжүүлэх; *dispatch latency* — энэ хугацаа.

**Хуваарилах шийдвэр гарах 4 нөхцөл:** ① ажиллаж байгаа → хүлээлт ② ажиллаж байгаа → бэлэн ③ хүлээлт → бэлэн ④ дуусах. Зөвхөн ①④ үед бол **nonpreemptive (буцаан авахгүй)**, бусад үед **preemptive (буцаан авах)**.

**Шалгуур:**

| Шалгуур | Тодорхойлолт | Зорилго |
|---|---|---|
| CPU ашиглалт | CPU завгүй байсан хувь | max |
| Нэвтрүүлэх чадвар (throughput) | нэгж хугацаанд дууссан процесс | max |
| **Эргэлтийн хугацаа (TAT)** | **дууссан − ирсэн** | min |
| **Хүлээлтийн хугацаа (WT)** | бэлэн дараалалд хүлээсэн нийт = **TAT − burst** | min |
| Хариу өгөх хугацаа | ирснээс анх CPU авах хүртэл | min |

**Алгоритмууд:**

| Алгоритм | Сонгох дүрэм | Preemptive? | Онцлог |
|---|---|---|---|
| **FCFS** | эрт ирсэн нь түрүүнд | Үгүй | Convoy effect (урт процессын ард богинонууд хүлээнэ) |
| **SJF** | CPU ээлж (burst) хамгийн богино | Үгүй (SRT — тийм) | Дундаж WT-ийн хувьд **оновчтой**; ирээдүйн burst-ийг таамаглах хэрэгтэй (экспоненциал дундаж) |
| **Эрэмбэлэлттэй** | эрэмбэ хамгийн өндөр | Аль аль нь | Starvation → **aging** шийдэл |
| **RR** | FCFS + **квант** q; дуусахгүй бол дарааллын төгсгөлд | Тийм | q их → FCFS; q бага → контекст сэлгэлт ихэснэ; burst-ийн ~80% нэг квантад дуусах ёстой |
| **Олон түвшинт дараалал** | дараалал бүр өөрийн алгоритм/эрэмбэтэй | — | Гэдрэг холбоотой (feedback) хувилбарт процесс дараалал хооронд шилжинэ |

## 4. Тайлангийн хариултууд — тайлбартай

### 5.1 — n процессын хэдэн хуваарь боломжтой вэ?
**n!** — эхний байрлалд n сонголт, дараагийнхад n−1, ... → n·(n−1)·…·1. (5 процесс → 120.)

### 5.2 — Preemptive ба nonpreemptive
Nonpreemptive — процесс CPU-г өөрөө (дуусах / I/O хүлээх) чөлөөлөх хүртэл эзэмшинэ. Preemptive — OS CPU-г буцааж авч болно (квант дуусах, өндөр эрэмбэтэй процесс ирэх). Орчин үеийн бүх OS preemptive; гэхдээ дундын өгөгдөлд **race condition** үүсгэж болно (Lec5 слайд 9).

### 5.3 — Nonpreemptive, P1(0.0, 8), P2(0.4, 4), P3(1.0, 1)

| | Gantt | TAT (P1, P2, P3) | Дундаж TAT |
|---|---|---|---|
| **a. FCFS** | P1 0–8, P2 8–12, P3 12–13 | 8, 11.6, 12 | **10.53** |
| **b. SJF** | P1 0–8 (0 мөчид ганцаараа!), P3 8–9, P2 9–13 | 8, 12.6, 8 | **9.53** |
| **c. 1 нэгж idle + SJF** | idle 0–1, P3 1–2, P2 2–6, P1 6–14 | 14, 5.6, 1 | **6.87** |

**Анхаар:** (b)-д 0 мөчид P2, P3 ирээгүй тул SJF ч P1-ийг сонгоно (nonpreemptive — дараа нь тасалж чадахгүй). (c) — "ирээдүйг мэддэг" бол сайжирна, гэвч бодит системд боломжгүй.

### 5.4 — Бүгд 0 мөчид, P1(2, эрэмбэ 2), P2(1, 1), P3(8, 4), P4(4, 2), P5(5, 3)

| Алгоритм | Gantt | WT (P1–P5) | Дундаж WT |
|---|---|---|---|
| **FCFS** | P1 0–2, P2 –3, P3 –11, P4 –15, P5 –20 | 0, 2, 3, 11, 15 | 6.2 |
| **SJF** | P2 0–1, P1 –3, P4 –7, P5 –12, P3 –20 | 1, 0, 12, 3, 7 | **4.6** ✅ хамгийн бага |
| **Эрэмбэ** (их тоо = өндөр) | P3 0–8, P5 –13, P1 –15, P4 –19, P2 –20 | 13, 19, 0, 15, 8 | 11.0 |
| **RR (q = 2)** | P1 0–2, P2 –3, P3 –5, P4 –7, P5 –9, P3 –11, P4 –13, P5 –15, P3 –17, P5 –18, P3 –20 | 0, 2, 12, 9, 13 | 7.2 |

- Эрэмбэ: P1, P4 хоёулаа 2 → **FCFS дарааллаар** (P1 түрүүнд).
- RR: дараалал P1,P2,P3,P4,P5 → P1 (2, дууслаа), P2 (1, дууслаа), P3 (2 ажиллаж үлдэгдэл 6 → төгсгөлд), P4 (2, үлд 2), P5 (2, үлд 3), P3 (үлд 4), P4 (дууслаа), P5 (үлд 1), P3 (үлд 2), P5 (дууслаа), P3 (дууслаа).
- TAT-ийн хүснэгт тайланд бий (бүгд 0-д ирсэн тул TAT = дууссан хугацаа).

### 5.5 — Preemptive эрэмбэ + RR (q = 10), их тоо = өндөр эрэмбэ

| Процесс | Эрэмбэ | Burst | Ирэх |
|---|---|---|---|
| P1 | 40 | 20 | 0 |
| P2 | 30 | 25 | 25 |
| P3 | 30 | 25 | 30 |
| P4 | 35 | 15 | 60 |
| P5 | 5 | 10 | 100 |
| P6 | 10 | 10 | 105 |

**Gantt:** `P1 0–20 | idle 20–25 | P2 25–35 | P3 35–45 | P2 45–55 | P3 55–60 | P4 60–75 | P2 75–80 | P3 80–90 | idle 90–100 | P5 100–105 | P6 105–115 | P5 115–120`

Гол мөчүүд:
- **10:** P1-ийн квант дууссан ч өөр процесс байхгүй → үргэлжилнэ.
- **35, 45:** P2, P3 ижил эрэмбэ (30) → RR-ээр ээлжилнэ.
- **60:** P4 (35) ирж P3-ийг **буцаан авна** (preempt) → P3 дарааллын **төгсгөлд** (P2-ийн ард).
- **105:** P6 (10) > P5 (5) → P5-ийг буцаан авна.

| | P1 | P2 | P3 | P4 | P5 | P6 |
|---|---|---|---|---|---|---|
| Дууссан | 20 | 80 | 90 | 75 | 120 | 115 |
| **TAT** | 20 | 55 | 60 | 15 | 20 | 10 |
| **WT** | 0 | 30 | 35 | 0 | 10 | 0 |

**CPU ашиглалт** = ажилласан / нийт = (20+25+25+15+10+10) / 120 = 105/120 = **87.5%** (idle: 20–25, 90–100 = 15 нэгж).

### 5.6 — Олон түвшинт дараалалд өөр өөр квант
Дээд (интерактив, I/O-bound) дараалал — **богино квант** → хурдан хариу. Доод (CPU-bound, batch) — **урт квант** → цөөн контекст сэлгэлт, бага overhead.

### 5.7 — Алгоритмын олонлогуудын хамаарал
- **a.** Priority ⊃ SJF — эрэмбэ = дараагийн CPU ээлжийн урвуу.
- **b.** MLFQ ⊃ FCFS — нэг дараалал, хязгааргүй квант = FCFS.
- **c.** Priority ⊃ FCFS — эрэмбэ = ирсэн хугацаа (эрт ирсэн нь өндөр).
- **d.** RR ба SJF — **хамааралгүй**.

### 5.8 — Ойрын хугацаанд CPU бага хэрэглэсэнийг илүүд үзэх алгоритм
I/O-bound процессууд богино ээлжээр CPU хэрэглэдэг → ойрын хэрэглээ бага → илүүд үзэгдэнэ. CPU-bound процесс өлсөхгүй: ① I/O-bound-ууд I/O хүлээж байхад CPU сул байна ② CPU-bound хүлээх тусам "ойрын хэрэглээ" нь буурч эрэмбэ нь өснө (**aging**-тай адил).

### 5.9 — PCS ба SCS
**PCS** — урсгалын сан хэрэглэгчийн урсгалуудыг LWP дээр хуваарилна, өрсөлдөөн **нэг процесс дотор** (many-to-one, many-to-many). **SCS** — кернел кернелийн урсгалуудыг CPU дээр, өрсөлдөөн **систем дэх бүх урсгал** (one-to-one: Linux, Windows). `PTHREAD_SCOPE_PROCESS` / `PTHREAD_SCOPE_SYSTEM`; Linux, macOS зөвхөн SYSTEM-ийг дэмждэг (Lec5 слайд 35).

### 5.10 — Уламжлалт UNIX: Priority = recent CPU / 2 + 60
P1: 40/2 + 60 = **80**, P2: 18/2 + 60 = **69**, P3: 10/2 + 60 = **65**. Тоо их = эрэмбэ бага → CPU их хэрэглэсэн (CPU-bound) процессын **эрэмбийг бууруулдаг**.

| Асуулт | Товч хариулт |
|---|---|
| SJF яагаад оновчтой вэ? | Богино процессыг урт процессын өмнө шилжүүлэх бүрд богиногийн хүлээлт буурах нь уртынх өсөхөөс их → дундаж WT хамгийн бага. |
| SJF-ийн гол асуудал? | Дараагийн CPU ээлжийн уртыг мэдэхгүй — экспоненциал дундажаар таамаглана: τₙ₊₁ = α·tₙ + (1−α)·τₙ, ихэвчлэн α = ½. |
| SRT гэж юу вэ? | SJF-ийн preemptive хувилбар — шинэ процесс ирэх бүрт үлдсэн хугацаа хамгийн бага нь ажиллана. |
| Starvation ба aging? | Бага эрэмбэтэй процесс хэзээ ч ажиллахгүй байх; aging — хүлээх тусам эрэмбийг нь нэмэгдүүлэх. |
| RR-ийн квантыг яаж сонгох вэ? | Контекст сэлгэлтийн хугацаанаас хангалттай их, CPU ээлжийн ~80% нэг квантад дуусахаар. |
| Convoy effect? | FCFS-д нэг урт CPU-bound процессын ард олон богино I/O-bound процесс хүлээх. |
| Linux CFS юугаар сонгодог вэ? | Хамгийн бага `vruntime` (виртуал ажилласан хугацаа)-тай таскийг; nice −20…+19 нь жинг тодорхойлно. |
| Processor affinity? | Урсгал өмнө ажилласан CPU-ийнхаа кэшийг ашиглахын тулд тэр CPU дээр үлдэх хандлага (soft / hard affinity). |
| Little-ийн томьёо? | n = λ × W (дарааллын дундаж урт = ирэх давтамж × дундаж хүлээлт). |
