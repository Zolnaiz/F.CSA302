## 1. Онол — товч

- **Шаардлагаар хуудаслах (demand paging)** — хуудсыг зөвхөн хандах үед санах ойд авчирна. Байхгүй хуудсанд хандвал **page fault** → OS хуудсыг swap-аас уншаад зааврыг дахин эхлүүлнэ (10.1).
- **Хуудас солих** — чөлөөт фрэйм байхгүй үед аль хуудсыг гаргах вэ:
  - **FIFO** — хамгийн эрт орсныг. Энгийн, гэхдээ **Belady-ийн аномали**: фрэйм нэмэхэд fault өсөж болно.
  - **OPT** — ирээдүйд хамгийн сүүлд хэрэглэгдэхийг. Хамгийн бага fault, бодитоор хэрэгжихгүй (ирээдүйг мэдэхгүй) — харьцуулах жишиг.
  - **LRU** — хамгийн удаан хэрэглэгдээгүйг. OPT-ийн сайн ойролцоолол. OPT, LRU — стек алгоритм, Belady-гүй (10.3).
- **Thrashing** — процесс ажиллахаасаа илүү хуудаслалт хийх; CPU бага, диск их ачаалалтай (10.13a).
- **Locality** — массивыг санах ойн дарааллаар явуулбал fault 100 дахин цөөрнө (10.7).

## 2. Программ — `page_replace.c` (10.44)

- Санамсаргүй 0–9 хуудасны мөр (`rand() % 10`), фрэймийн тоо командын мөрөөс (1–64).
- `fifo()` — тойрог дарааллын толгойг солино. `lru()` — фрэйм бүрийн сүүлд хандсан индекс, хамгийн бага нь гарна. `opt()` — фрэйм бүрийн хуудас дараа нь хэзээ хэрэглэгдэхийг хайж, хамгийн холыг гаргана.
- `-r "..."` — тодорхой мөр өгч номын жишээгээр шалгана. Буруу оролт (0 фрэйм, 10+ хуудас, үсэг) → алдаа, exit 1.

## 5. Багш асууж магадгүй

| Асуулт | Хариулт |
|---|---|
| OPT-г яагаад бодит системд хэрэглэдэггүй? | Ирээдүйн хандалтыг мэдэх боломжгүй. Зөвхөн бусад алгоритмыг харьцуулах жишиг. |
| LRU-г техник хангамжид хэрхэн хэрэгжүүлдэг? | Тоолуур (хандалт бүрт цаг) эсвэл стек — үнэтэй. Иймээс reference бит, second-chance (clock)-оор ойролцоолно. |
| Belady-ийн аномали гэж юу вэ? | Фрэйм нэмэхэд page fault өсөх. FIFO-д гардаг, стек алгоритмд (LRU, OPT) гардаггүй. |
| 10.7-д яагаад 5000 ба 50? | Массив мөрөөр хадгалагдана, хуудсанд 2 мөр. Баганаар явбал багана бүрт бүх 50 хуудсаар гарна. |
| Thrashing-ийг яаж илрүүлэх вэ? | CPU ашиглалт бага, хуудаслах диск дүүрэн (10.13a). Шийдэл — мультипрограммчлалын түвшинг бууруулах. |
